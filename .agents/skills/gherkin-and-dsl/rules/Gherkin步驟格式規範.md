# Rule 1 - 語言、關鍵字與註解

- 使用 `zh-TW` 的 feature，第一行必須是 `# language: zh-TW`。
- 步驟關鍵字必須使用 `假設`、`當`、`那麼`、`而且`。關鍵字後面不得加冒號。
- 註解必須是整行，而且以 `#` 開頭。
- 會改變讀者如何理解該步驟的預設，必須寫成緊鄰步驟上方的整行註解，格式為 `# 參數="值"`。

## Good Example

- 預設商品編號寫在步驟上方，步驟關鍵字後面沒有冒號。

```gherkin
# language: zh-TW
功能: 結帳

    場景: EC-2.3 購物車有 SKU-1001 兩件、配送地區台北市
      # 商品編號="SKU-1001"
      # 數量="2"
      假設 購物車已有商品
      當 "會員A" 以配送地區 "台北市" 結帳
```

## Bad Example

- 預設藏在行尾註解，而且步驟關鍵字後面加了冒號。

```gherkin
    場景: EC-2.3 購物車有 SKU-1001 兩件、配送地區台北市
      假設: 購物車已有商品 # 商品編號=SKU-1001
      當: "會員A" 以配送地區 "台北市" 結帳
```

# Rule 2 - 一個場景只有一個當

- 一個 `場景` 或一個 `場景大綱` 必須正好有一個 `當`。
- `當` 後面的 `而且` 仍屬於這一個動作，不得再寫第二個 `當`。
- `那麼` 必須使用「應該」寫出可觀察結果。
- 來源案例標成不驗證的事項，不得寫成步驟。

## Good Example

- 結帳是唯一的 `當`，結果用「應該」寫出。

```gherkin
      假設 購物車已有商品
      當 "會員A" 以配送地區 "台北市" 結帳
      那麼 "會員A" 看到的訂單應該符合
        | 訂單階段 |
        | 待付款 |
```

## Bad Example

- 同一個場景先加入商品、再結帳，出現兩個 `當`。

```gherkin
      當 "會員A" 把商品 "SKU-1001" 加入購物車 2 件
      那麼 購物車裡應該有 2 件商品
      當 "會員A" 以配送地區 "台北市" 結帳
      那麼 訂單階段應該是 "待付款"
```

# Rule 3 - 句中參數與表格參數的引號不同

- 句中的字串參數必須使用雙引號。
- 句中的整數參數不得加引號。
- Data Table 儲存格不得加引號。
- 可能含前導零的商品編號或代碼必須當作字串，不得寫成整數。

## Good Example

- 會員與商品編號是字串，數量是整數，表格裡沒有引號。

```gherkin
      當 "會員A" 把商品 "SKU-0042" 加入購物車 3 件
      那麼 "會員A" 看到的購物車應該符合
        | 商品編號 | 數量 |
        | SKU-0042 | 3 |
```

## Bad Example

- 含前導零的商品編號被寫成沒有引號的字，表格又把字串加上引號。

```gherkin
      當 會員A 把商品 SKU-0042 加入購物車 "3" 件
      那麼 "會員A" 看到的購物車應該符合
        | 商品編號 | 數量 |
        | "SKU-0042" | "3" |
```

# Rule 4 - 相同動作必須保留相同步驟文字

- 同一個動作出現在多個場景時，步驟文字必須相同，以便共用一個步驟定義。
- 不得為了消除重複步驟文字而改寫其中一句。
- 動作不同的步驟不得共用同一句文字。

## Good Example

- 兩組資料都是結帳，所以 `當` 的文字相同。

```gherkin
    場景大綱: EC-2.4 單價 500 元兩件的應付金額
      當 "會員A" 以配送地區 "<配送地區>" 結帳

    場景大綱: EC-2.4 單價 500 元兩件的訂單階段
      當 "會員A" 以配送地區 "<配送地區>" 結帳
```

## Bad Example

- 為了讓兩句看起來不同，把同一個結帳改成另一種說法。

```gherkin
    場景大綱: EC-2.4 單價 500 元兩件的應付金額
      當 "會員A" 以配送地區 "<配送地區>" 結帳

    場景大綱: EC-2.4 單價 500 元兩件的訂單階段
      當 "會員A" 送出 "<配送地區>" 的結帳請求
```
