# Rule 1 - 三層階層必須看得出

- `zh-TW` feature 的三層必須是 `功能`、`Rule`、`場景`。場景大綱的資料表關鍵字必須是 `例子`。
- `功能` 必須在第 0 欄。`Rule` 必須縮排在 `功能` 底下，不得與 `功能` 同在第 0 欄。
- 功能描述與功能 `背景` 必須縮排 2 格。功能 `背景` 的步驟必須縮排 4 格。
- `Rule` 必須縮排 2 格。Rule 的 `背景`、`場景` 與 `場景大綱` 必須縮排 4 格。這些區塊裡的步驟與 `例子` 必須縮排 6 格。表格必須比所屬步驟再縮排 2 格。
- 檔名必須使用與 feature 相同的語言，並且點出該檔受測的動作或面向。`zh-TW` feature 的檔名必須是繁體中文。

## Good Example

- `Rule` 在功能底下，場景大綱又在該 Rule 底下。

```gherkin
功能: 加入購物車

  背景:
    假設 購物車是空的

  Rule: 庫存足夠時必須把商品加入購物車

    場景大綱: EC-1.1 有庫存的商品與數量
      當 "會員A" 把商品 "<商品編號>" 加入購物車 <數量> 件
```

## Bad Example

- `Rule` 與 `功能` 同在第 0 欄，階層看不出 Rule 屬於這個功能。

```gherkin
功能: 加入購物車

  背景:
    假設 購物車是空的

Rule: 庫存足夠時必須把商品加入購物車

  場景大綱: EC-1.1 有庫存的商品與數量
    當 "會員A" 把商品 "<商品編號>" 加入購物車 <數量> 件
```

# Rule 2 - 一條 Rule 只證明一個主張

- Rule 名稱必須用繁體中文寫出被驗證的那一個主張。
- 名稱應該使用「某某必須某某」。主張無法用這個句型說清時，可以改用其他句型，但仍然只能有一個主張。
- 同一個 Rule 底下可以有多個 `場景` 或 `場景大綱`。它們必須是同一主張的不同資料、不同情境，或同一主張的不同觀察欄位。
- 場景標題描述的若是另一個主張，該場景必須改放到另一條 Rule。
- 不得為了讓每條 Rule 只剩一個場景，把同一主張的不同資料拆成多條 Rule。

## Good Example

- 應付金額與訂單階段是同一筆結帳的兩個觀察欄位，所以留在同一個 Rule。

```gherkin
  Rule: 可配送地區的結帳金額必須等於商品金額加運費

    場景大綱: EC-2.4 單價 500 元兩件的應付金額
      當 "會員A" 以配送地區 "<配送地區>" 結帳

    場景大綱: EC-2.4 單價 500 元兩件的訂單階段
      當 "會員A" 以配送地區 "<配送地區>" 結帳
```

## Bad Example

- 兩個場景只是同一筆結帳的兩個欄位，卻被拆成各自只有一個場景的 Rule。

```gherkin
  Rule: 結帳金額必須等於商品金額加運費

    場景大綱: EC-2.4 單價 500 元兩件的應付金額
      當 "會員A" 以配送地區 "<配送地區>" 結帳

  Rule: 結帳後訂單階段必須是待付款

    場景大綱: EC-2.4 單價 500 元兩件的訂單階段
      當 "會員A" 以配送地區 "<配送地區>" 結帳
```

# Rule 3 - 場景標題必須是資料情境

- `場景` 與 `場景大綱` 的標題必須指出這組資料或這個情境，不得把 Rule 的主張再寫一次。
- 既有案例編號可以留在標題前面。
- 兩個場景使用同一組輸入、只觀察不同欄位時，標題必須在資料名稱後面加上所看的欄位，使兩個標題不同。

## Good Example

- 標題寫的是哪一組商品與數量，沒有重述「庫存足夠必須加入」。

```gherkin
  Rule: 庫存足夠時必須把商品加入購物車

    場景大綱: EC-1.1 有庫存的商品與數量
```

## Bad Example

- 標題幾乎是 Rule 的同句，看不出這是哪一組商品。

```gherkin
  Rule: 庫存足夠時必須把商品加入購物車

    場景大綱: EC-1.1 庫存足夠時必須把商品加入購物車
```
