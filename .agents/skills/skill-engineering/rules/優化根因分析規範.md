# Rule 1 - 使用者期待必須可驗證

- 優化既有 Skill 時，必須先從使用者描述、相關對話脈絡或既有輸出中推導使用者期待。
- 使用者期待必須描述可比較的目標結果、管理要求或行為變化。
- 使用者期待不得只寫成「更好」、「更完整」或「不滿意」等無法驗證的描述。
- 使用者期待資訊不足時，必須先列出缺口並取得使用者補充或確認。

## Good Example

- 期待指出了目標結果與可比較行為，因此後續能做落差分析。

```text
使用者期待：優化後的 Skill 必須在修改既有 Skill 前，先指出造成輸出不滿意的 SOP 步驟與 Rule File，並取得使用者確認。
```

## Bad Example

- 期待只描述主觀改善，無法判斷後續改動是否達成目標。

```text
使用者期待：讓這個 Skill 變得更聰明。
```

# Rule 2 - 現況落差必須以執行結果回推

- 現況落差必須比較使用者期待與既有 Skill 實際造成的結果。
- 回推時必須檢查目標 Skill 的 `SKILL.md`、已載入的 Rule File、Template、Script 及上下游委派 Skill。
- 回推必須沿著 SOP 實際執行順序描述問題如何產生。
- 不得只根據檔案名稱或單一片段推定根因。

## Good Example

- 落差由輸出結果回推到 SOP、Rule File 與上下游委派關係。

```text
現況落差：使用者期待先做根因確認，但既有 SOP 在讀取需求後直接進入 Deriver 編排。
回推路徑：skill-engineering/SKILL.md Phase 3 缺少確認閘門，且沒有 Rule File 定義如何比較期待與現況。
```

## Bad Example

- 判斷只看檔名，沒有沿著執行流程推導問題。

```text
現況落差：因為 rules 目錄檔案太少，所以輸出不好。
```

# Rule 3 - 根因必須定位到可修改部位

- 根因必須指出具體 Skill、檔案、Phase、步驟、Rule、Template 或 Script 職責。
- 根因必須說明該部位如何導致使用者期待與現況的落差。
- 根因分析必須列出主要根因與非根因排除項目。
- 不得把「需要優化整個 Skill」當成根因。

## Good Example

- 根因定位到具體 Phase 與缺失，並排除了不是主因的部位。

```text
主要根因：skill-engineering/SKILL.md Phase 3 沒有在優化模式中要求使用者確認根因提案。
非根因排除：skill-derive-rule 可正確衍生 Rule File，但它只負責指定步驟，不負責判斷整體優化根因。
```

## Bad Example

- 根因過於籠統，無法指導刪改或重構。

```text
主要根因：這組 Skills 的設計還不夠好。
```

# Rule 4 - 根因確認提案必須成為改寫閘門

- 進入優化改寫前，必須先提出根因確認提案。
- 根因確認提案必須包含使用者期待、現況落差、回推路徑、主要根因、非根因排除與改造方向。
- 使用者未確認根因確認提案前，不得修改目標 Skill 的 SOP、Rule File、Template 或 Script。
- 使用者修正期待或不同意根因時，必須重新分析，不得沿用原根因提案。

## Good Example

- 提案內容完整且明確要求確認後才進入改寫。

```text
根因確認提案：
- 使用者期待：優化前先定位造成不滿意結果的 Skill 部位。
- 現況落差：既有流程直接進入模組衍生。
- 回推路徑：Phase 3 缺少確認閘門。
- 主要根因：SOP 未要求根因提案與使用者確認。
- 非根因排除：Deriver 本身不是主要問題。
- 改造方向：新增根因分析 Rule File 並將確認點寫入 SOP。
確認後才進入改寫。
```

## Bad Example

- 沒有確認閘門，直接把推測當成改寫依據。

```text
我猜問題是規則太少，所以直接新增一份 Rule File。
```

# Rule 5 - 優化目標是消除根因而非最小修改

- 優化既有 Skill 時，必須以消除已確認根因為目標。
- 當根因來自錯誤流程、過時模組、重複規則或錯誤委派邊界時，必須重寫、刪除、合併或重切職責。
- 不得為了保留既有內容而疊加補丁式步驟或重複規則。
- 保留既有部位時，必須能說明該部位仍服務於已確認的目標流程。

## Good Example

- 改造方向直接處理根因，並允許刪除過時模組。

```text
改造方向：刪除未被 SOP 載入的舊規則，重寫 Phase 3 的根因確認流程，並只保留會被新流程使用的 Rule File。
```

## Bad Example

- 在錯誤主幹上疊加補丁，沒有消除根因。

```text
改造方向：保留原本會直接改寫的流程，再新增一條提醒代理要小心。
```
