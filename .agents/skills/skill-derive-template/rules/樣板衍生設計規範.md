# Rule 1 - Template 與 Rule File 的選用條件

- 只有當指定步驟會生成具有固定檔案內容結構的輸出時，才可以衍生 Template。
- 固定檔案內容結構必須能以可重用的骨架及對應的完整範例表達。
- 行為約束、品質標準或判斷條件必須使用 Rule File 表達。
- Template 不得取代行為約束、品質標準或判斷條件所需的 Rule File。
- 指定步驟沒有固定檔案輸出結構時，不得衍生 Template。

## Good Example

- 指定步驟固定生成具有標題、摘要及檢查清單的報告檔案，因此可以用骨架與範例表達固定結構。

```text
指定步驟：Write 生成固定包含「標題、摘要、檢查清單」的稽核報告檔案。
衍生方式：建立稽核報告骨架及其完整範例。
```

## Bad Example

- 指定步驟只需要判斷報告品質，沒有生成固定結構的檔案，卻以 Template 表達品質約束。

```text
指定步驟：Think 判斷稽核報告是否清楚。
衍生方式：建立「內容必須清楚」的 Template。
```

# Rule 2 - Template 名稱與成對路徑

- Template 名稱必須描述指定步驟生成的單一檔案內容結構。
- 骨架路徑必須使用相對於目標 Skill `SKILL.md` 的 `templates/<名稱>.<格式>` 形式。
- 範例路徑必須使用相對於目標 Skill `SKILL.md` 的 `templates/<名稱>.example.<格式>` 形式。
- 範例檔名中的 `example` 必須使用小寫英文字母。
- `<格式>` 必須使用指定步驟實際生成檔案的副檔名。
- 骨架與範例必須使用相同的 `<名稱>` 及 `<格式>`。
- 路徑不得覆寫與本次固定結構不同的既有檔案。

## Good Example

- 兩條路徑位於 `templates/`，共用名稱與格式，且範例使用小寫 `example`。

```text
templates/稽核報告.md
templates/稽核報告.example.md
```

## Bad Example

- 範例使用大寫 `Example`、不同名稱及不同格式，無法識別為同一組 Template。

```text
templates/稽核報告.md
templates/完整報告.Example.txt
```

# Rule 3 - 骨架與範例必須成對

- 每次衍生 Template 必須同時建立骨架與範例兩個檔案。
- 骨架必須呈現可重用的固定結構及待填內容位置。
- 範例必須依同一份骨架提供完整且具體的成品。
- 骨架與範例必須涵蓋相同的固定結構。
- 不得只建立、修改或整合骨架與範例中的其中一個檔案。

## Good Example

- 同時建立骨架與完整範例，且兩者都有相同的標題與摘要結構。

```markdown
<!-- templates/稽核報告.md -->
# {{REPORT_TITLE}}

## 摘要

{{SUMMARY}}

<!-- templates/稽核報告.example.md -->
# API 安全稽核

## 摘要

本報告記錄 API 驗證機制的稽核結果。
```

## Bad Example

- 只建立骨架，缺少必須成對提供的範例檔案。

```markdown
<!-- templates/稽核報告.md -->
# {{REPORT_TITLE}}

## 摘要

{{SUMMARY}}
```

# Rule 4 - Template 載入位置與方式

- 骨架與範例必須在指定步驟首次需要其內容時載入。
- 骨架與範例的 `Read` 步驟必須與指定步驟位於同一個 Phase。
- 骨架與範例的 `Read` 步驟必須共同緊鄰指定步驟之前。
- 骨架與範例應該各自使用一個 `Read` 步驟載入。
- 未分開載入骨架與範例時，必須說明無法分開的具體理由。
- 每個 `Read` 步驟必須明確指出所載入的路徑及要取得的內容。
- 不得為載入骨架與範例建立獨立 Phase。
- 不得在同一次 SOP 執行中重複載入相同的骨架或範例。

## Good Example

- 骨架與範例在指定步驟首次需要時，於同一 Phase 以兩個相鄰的 `Read` 步驟分別載入。

```markdown
## Phase 2: 生成稽核報告

1. Think 決定報告主題。
2. Read [稽核報告骨架](templates/稽核報告.md)並取得固定內容結構。
3. Read [稽核報告範例](templates/稽核報告.example.md)並取得完整使用方式。
4. Write 依已載入樣板與範例生成稽核報告檔案。
```

## Bad Example

- 骨架與範例被提前放入獨立 Phase，沒有在指定步驟首次需要時載入。

```markdown
## Phase 1: 載入 Template

1. Read [稽核報告骨架](templates/稽核報告.md)並取得固定內容結構。
2. Read [稽核報告範例](templates/稽核報告.example.md)並取得完整使用方式。

## Phase 2: 生成稽核報告

1. Write 依已載入樣板與範例生成稽核報告檔案。
```

# Rule 5 - 整合 Template 時保留指定步驟

- 指定步驟必須使用「已載入樣板與範例」指稱已載入的骨架與範例。
- 指定步驟必須保留原有的步驟動詞。
- 指定步驟必須保留原有的行為目的。
- 加入 `Read` 步驟後，所屬 Phase 的步驟必須依執行順序重新連續編號。
- 未被指定的步驟必須保留原有內容與順序。
- 指定步驟所屬 Phase 必須保留原有目的及位置。
- 不得修改與本次 Template 整合無關的 Phase 或步驟。

## Good Example

- 指定步驟保留原有 `Write` 動詞及生成稽核報告的目的，並使用指定措辭；其他步驟與 Phase 也維持原狀。

```markdown
## Phase 2: 生成稽核報告

1. Think 決定報告主題。
2. Read [稽核報告骨架](templates/稽核報告.md)並取得固定內容結構。
3. Read [稽核報告範例](templates/稽核報告.example.md)並取得完整使用方式。
4. Write 依已載入樣板與範例生成稽核報告檔案。
5. Read 檢查稽核報告是否存在。
```

## Bad Example

- 指定步驟由 `Write` 改為 `Think`、改變原有目的，且沒有使用「已載入樣板與範例」。

```markdown
## Phase 2: 生成稽核報告

1. Read [稽核報告骨架](templates/稽核報告.md)並取得固定內容結構。
2. Read [稽核報告範例](templates/稽核報告.example.md)並取得完整使用方式。
3. Think 依參考內容評估稽核報告。
```

# Rule 6 - 回填 SOP 的成對整合

- 回填目標 SOP 時，必須明確包含骨架與範例兩條相對路徑。
- 兩條路徑必須分別指向本次建立的骨架與範例檔案。
- 骨架與範例的載入步驟必須共同服務於同一個指定步驟。
- 不得只將骨架或範例其中一條路徑整合至目標 SOP。
- 不得以 `templates/` 目錄或「相關 Template」等不明確描述取代兩條檔案路徑。

## Good Example

- 目標 SOP 明確列出同一組骨架與範例的兩條路徑。

```markdown
1. Read [稽核報告骨架](templates/稽核報告.md)並取得固定內容結構。
2. Read [稽核報告範例](templates/稽核報告.example.md)並取得完整使用方式。
3. Write 依已載入樣板與範例生成稽核報告檔案。
```

## Bad Example

- 目標 SOP 只列出骨架路徑，沒有整合對應的範例路徑。

```markdown
1. Read [稽核報告骨架](templates/稽核報告.md)並取得固定內容結構。
2. Write 依已載入樣板與範例生成稽核報告檔案。
```
