# Rule 1 - 任務都完成才把規格標成 Implemented

- `tasks.md` 沒有未完成任務，且目標 `spec.md` 存在時，必須把該檔的狀態列改為 `Implemented`。
- 未完成任務是 checkbox 為 `[ ]`、且同一行含任務 ID 的清單項。
- `**Checkpoint**`、`**Checkpoint status**`、`STOP and VALIDATE`、`MVP First` 與 `MVP 止於` 不得影響完成狀態的寫入條件。
- 狀態列已經是 `Implemented` 時，必須保持 `Implemented`。
- 沒有未完成任務、目標 `spec.md` 存在、且憲法沒有停止寫入時，狀態列為 `Implemented` 才是符合狀態。
- 目標 `spec.md` 不存在時，規格狀態為空是符合狀態。
- 寫入時不得修改 `spec.md` 的其他內容。
- 目標 `spec.md` 不存在時，不得建立 `spec.md`。

## Good Example

- 任務都已打勾，因此只把狀態列改成已實作。

```markdown
- [X] T001 建立目錄
- [X] T002 初始化 backend 專案
**狀態 ( Status )**：Implemented
```

## Bad Example

- 任務都已打勾，卻連需求本文一起改寫。

```markdown
- [X] T001 建立目錄
- [X] T002 初始化 backend 專案
**狀態 ( Status )**：Implemented
**FR-US1-001**: 已改寫的需求本文
```

# Rule 2 - 憲法停止寫入時不得改狀態

- 憲法停止寫入 `spec.md` 時，不得修改狀態列。
- 憲法停止寫入時，必須把拒絕原因寫入回覆。
- 憲法停止寫入時，狀態列維持原值是符合狀態。

## Good Example

- 憲法停止寫入，因此狀態維持原值，並在回覆說明原因。

```markdown
憲法 Rule：停止寫入 spec.md
**狀態 ( Status )**：Ready for Planning
回覆：拒絕更新規格狀態，因為憲法停止寫入 spec.md。
```

## Bad Example

- 憲法已停止寫入，卻仍把狀態改成已實作。

```markdown
憲法 Rule：停止寫入 spec.md
**狀態 ( Status )**：Implemented
回覆：規格狀態已更新為 Implemented。
```
