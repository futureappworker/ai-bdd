# Rule 1 - 未完成的規格品質清單必須先詢問

- feature 目錄的 `checklists/` 存在，且其中任一 checklist 項目仍是 `[ ]` 時，必須把本次決定為停下詢問。
- 停下詢問的回覆必須列出未完成項目，並詢問是否繼續。
- 停下詢問之後必須停止本次 SOP 的所有後續步驟。
- 停下詢問時不得開始任何任務。

## Good Example

- 規格品質清單還有未勾項目，因此先詢問，不開始 T001。

```markdown
checklists/requirements.md
- [ ] 需求可測試且沒有歧義
- [X] 規格中沒有洩漏實作細節

本次決定：停下詢問
回覆：checklist 尚未完成「需求可測試且沒有歧義」。是否繼續實作？
任務：尚未開始
```

## Bad Example

- 規格品質清單還有未勾項目，卻直接開始任務。

```markdown
checklists/requirements.md
- [ ] 需求可測試且沒有歧義

本次決定：繼續執行任務
目標任務：T001
```

## Exceptions

- 使用者輸入明確寫出略過規格品質清單或略過 checklist 時，不得因未完成項目停下詢問。

# Rule 2 - 清單已完成或不存在時必須繼續

- feature 目錄沒有 `checklists/` 時，本次決定必須是繼續執行任務。
- `checklists/` 存在且每個 checklist 項目都是 `[X]` 時，本次決定必須是繼續執行任務。
- 繼續執行任務時不得詢問是否繼續。

## Good Example

- 規格品質清單全數勾選，因此直接繼續，不再詢問。

```markdown
checklists/requirements.md
- [X] 需求可測試且沒有歧義
- [X] 規格中沒有洩漏實作細節

本次決定：繼續執行任務
```

## Bad Example

- 規格品質清單已經全部勾選，卻仍停下詢問。

```markdown
checklists/requirements.md
- [X] 需求可測試且沒有歧義
- [X] 規格中沒有洩漏實作細節

本次決定：停下詢問
回覆：是否繼續實作？
```
