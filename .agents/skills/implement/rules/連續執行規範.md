# Rule 1 - 任務已打勾就回到下一個任務

- 本次目標任務的 checkbox 為 `[X]` 時，下一個執行位置必須是 Phase 3。
- 任務之間不得詢問使用者是否繼續。
- `STOP and VALIDATE`、`MVP First`、`MVP 止於`、`Parallel Opportunities` 與使用者指定的任務 ID 不得作為進入 Phase 15 的條件。

## Good Example

- T002 已打勾，後面還有 T003，因此回到選擇下一個任務。

```markdown
- [X] T002 初始化 backend 專案
- [ ] T003 初始化 frontend 專案

本次目標任務：T002
下一個執行位置：Phase 3
```

## Bad Example

- T002 已打勾且 T003 尚未完成，卻結束本次執行。

```markdown
- [X] T002 初始化 backend 專案
- [ ] T003 初始化 frontend 專案

本次目標任務：T002
下一個執行位置：Phase 15
```

# Rule 2 - 任務未能打勾就結束本次執行

- 本次目標任務的 checkbox 仍是 `[ ]` 時，下一個執行位置必須是 Phase 15。
- checkbox 仍是 `[ ]` 只發生在憲法停止寫入 `tasks.md`。
- 結束回覆不得詢問使用者是否繼續。

## Good Example

- 憲法停止寫入 checkbox，T002 維持未完成，因此結束本次執行。

```markdown
憲法 Rule：停止寫入 tasks.md
- [ ] T002 初始化 backend 專案

本次目標任務：T002
下一個執行位置：Phase 15
```

## Bad Example

- 憲法已停止寫入 checkbox，卻回去做下一個任務。

```markdown
憲法 Rule：停止寫入 tasks.md
- [ ] T002 初始化 backend 專案

本次目標任務：T002
下一個執行位置：Phase 3
```

# Rule 3 - Phase 15 只在允許結束時進入

- `tasks.md` 仍有 checkbox 為 `[ ]` 的任務，且本次目標任務已成功打勾為 `[X]` 時，下一個執行位置必須是 Phase 3，不得進入 Phase 15。
- 進入 Phase 15 的允許情況只有：`tasks.md` 已無未完成任務（接 Phase 12 完成路徑），或憲法停止寫入 `tasks.md` 導致本次目標任務無法打勾。
- 同一輪 `/implement` 必須在允許範圍內盡可能連續執行 Phase 3→Phase 10 迴圈，直到無未完成任務或命中上述硬阻擋。
- 回覆不得把「再呼叫 /implement」「再執行一次 /implement」當成正常結束後的建議下一步；不得在尚有未完成任務時，用進度摘要或 checkpoint 名稱暗示可以收工。
- 若因回合或環境限制無法在同一回覆內繼續下一個任務，仍須在回覆中標明 **implement 未跑完**，並寫出文件順序上的下一個未完成任務 ID；不得偽裝成已依 SOP 正常結束。

## Good Example

- 全部任務已 `[X]`，進入 Phase 12 後再 Phase 15 回報完成。

```markdown
- [X] T069 …
- [X] T070 …

本次：無未完成任務
下一個執行位置：Phase 12 → Phase 15
回覆：全部 70 項任務已完成
```

## Bad Example

- T010 仍是 `[ ]`，卻結束並建議使用者再叫 /implement。

```markdown
- [X] T009 …
- [ ] T010 …

回覆：已完成 T001–T009。再執行 /implement 會從 T010 繼續。
```

# Rule 4 - 能繼續就必須繼續做到完成

- 預設目標是 **同一輪使用者訊息內** 盡量跑完 `tasks.md` 全部任務，而不是每做幾項就結束回覆。
- 本次目標任務已打勾、仍有未完成任務、且 **未命中硬阻擋** 時，必須在同一輪內回到 Phase 3，不得進入 Phase 15，不得先寫給使用者的進度摘要、checkpoint 報告或「本輪完成 Txxx–Tyyy」式收工。
- **硬阻擋**（才可停在做完當前可打勾任務之後、並進 Phase 15）只包含：
  - Phase 2：規格品質 checklist 未完成且使用者未允許略過；
  - Phase 8：憲法停止寫入 `tasks.md`，導致無法打勾；
  - Phase 6～7：本次目標任務驗證在依規範修正後仍無法通過，且已依 [任務驗證規範](任務驗證規範.md) 完成修正嘗試；
  - Phase 4～5：任務 References 無效、契約與測試矛盾且無法在不違規格下修正，需使用者決策；
  - 使用者明確要求停止或縮小範圍。
- **不得**因下列理由提前 Phase 15：任務很多、已跨使用者故事、已達 MVP、想整理摘要、token 或篇幅「看起來夠長」、或慣性結束回合。
- **環境上限**：若已無法再執行下一任務所需的工具（例如無法再跑測試或寫檔），才可因環境上限進 Phase 15；回覆必須標 **implement 未跑完**、簡述阻礙，並寫出下一個未完成任務 ID。在工具仍可用的情況下，不得以此為由收工。
- tasks 全部 `[X]` 後，依 Phase 12 更新 `spec.md`，再 Phase 15 回報 **全部完成**。

## Good Example

- T039 打勾後 T040 仍 `[ ]`，無硬阻擋，同一輪繼續 T040，不先回覆使用者。

```markdown
本次目標任務：T039 [X]
tasks.md：仍有 T040…
硬阻擋：無
下一個執行位置：Phase 3（同一輪繼續，無使用者可見回覆）
```

## Bad Example

- T039 打勾後以「implement 未跑完、下一個 T040」收工，但尚未嘗試 T040 且工具仍可用。

```markdown
本次目標任務：T039 [X]
回覆：本輪完成 T010–T039，未跑完，下一個 T040
（未執行 T040 即 Phase 15）
```
