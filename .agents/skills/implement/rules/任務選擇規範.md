# Rule 1 - 一次只選文件順序上的第一個未完成任務

- 未完成任務是 `tasks.md` 中 checkbox 為 `[ ]`、且同一行含任務 ID 的清單項。
- 有未完成任務時，本次目標任務必須是文件由上到下的第一個未完成任務。
- 同一次只允許一個目標任務。
- `[P]` 不得用來把另一個任務加入本次目標。
- 不得跳過文件順序中更前面的未完成任務。

## Good Example

- T002 是文件順序上第一個未完成任務，因此只選 T002。

```markdown
- [X] T001 建立目錄
- [ ] T002 初始化 backend 專案
- [ ] T003 [P] 初始化 frontend 專案

本次目標任務：T002
```

## Bad Example

- 因為 T003 標了 `[P]`，就把 T002 與 T003 同時選進本次目標。

```markdown
- [X] T001 建立目錄
- [ ] T002 初始化 backend 專案
- [ ] T003 [P] 初始化 frontend 專案

本次目標任務：T002、T003
```

# Rule 2 - 非任務文字不得參與選擇

- `**Checkpoint**`、`**Checkpoint status**`、`STOP and VALIDATE`、`MVP First`、`MVP 止於` 與 `Parallel Opportunities` 都不是任務。
- 上述文字不得被選為目標任務。
- 上述文字不得當成還有未完成任務。
- 使用者指定的任務 ID 不得縮小本次要完成的任務範圍。

## Good Example

- Checkpoint 留在原位，下一個目標仍是第一個未完成任務。

```markdown
- [X] T005 掛載房間路由骨架

**Checkpoint**: 資料庫連線與 HTTP 伺服器骨架可用

- [ ] T006 [US1] 紅燈：寫入 BE-1.1

本次目標任務：T006
```

## Bad Example

- 把 Checkpoint 當成下一個目標，T006 留著不做。

```markdown
- [X] T005 掛載房間路由骨架

**Checkpoint**: 資料庫連線與 HTTP 伺服器骨架可用

- [ ] T006 [US1] 紅燈：寫入 BE-1.1

本次目標任務：驗證 Checkpoint
```
