# Rule 1 - 只載入目標任務的 References

- 執行目標任務時，必須只載入該任務正下方列出的 `References` 位址。
- 每一行 `References` 必須視為獨立載入邊界。
- 不得因為某個 `References` 指向 OpenAPI、DBML、interface 或 techstack，就讀取同一份文件中未被該任務列出的其他部位。
- 若 `References` 位址無法解析，必須停止該任務並回報缺少或無效的位址。

## Good Example

- 任務只引用 `GuessRecord`，因此只載入該 schema。

```markdown
- [ ] T017 [US1] 撰寫 1A2B 計分單元測試
  - **References**: `contracts/openapi.yaml#/components/schemas/GuessRecord`

載入：GuessRecord
不載入：SubmitGuessPayload、GameView、整份 openapi.yaml
```

## Bad Example

- 任務只引用一個 schema，卻讀取整份契約。

```markdown
- [ ] T017 [US1] 撰寫 1A2B 計分單元測試
  - **References**: `contracts/openapi.yaml#/components/schemas/GuessRecord`

載入：整份 contracts/openapi.yaml
```

# Rule 2 - 端點邊界不得混用

- 後端任務不得為了目標任務讀取 DBML table 或前端 frame，除非該任務的 `References` 明確列出同一後端端點需要的部位。
- 資料庫任務不得讀取 OpenAPI operation 或前端 frame。
- 前端任務不得讀取 DBML table 或 OpenAPI operation，除非任務描述明確要求前端處理該 payload 且 `References` 指向該部位。
- 任務描述與 `References` 衝突時，必須回報衝突而不是自行擴大讀取範圍。

## Good Example

- 資料庫任務只讀取 DBML table。

```markdown
- [ ] T023 [US1] 在 backend/src/db/snapshot.ts 寫入 guesses
  - **References**: `contracts/schema.dbml#Table/guesses`

載入：Table/guesses
不載入：SubmitGuessPayload、game-in-progress frame
```

## Bad Example

- 資料庫任務讀取了不屬於該端點的 OpenAPI 與 UI frame。

```markdown
- [ ] T023 [US1] 在 backend/src/db/snapshot.ts 寫入 guesses
  - **References**: `contracts/schema.dbml#Table/guesses`

載入：Table/guesses、SubmitGuessPayload、game-in-progress frame
```

# Rule 3 - 原始碼讀取必須服務於目標任務

- 可以讀取目標任務描述中的目標檔案。
- 可以讀取同目錄相鄰檔案、既有測試檔或呼叫端檔案，以取得實作模式。
- 不得掃描整個 repository 來尋找與目標任務無直接關係的重構機會。
- 若需要額外讀取未被任務描述提到的檔案，必須能說明該檔案與目標任務的直接關係。

## Good Example

- 實作 `scoreGuess` 時讀取目標檔與對應測試檔。

```markdown
目標任務：在 backend/src/game/one-a-two-b.ts 實作 scoreGuess
可以讀取：backend/src/game/one-a-two-b.ts
可以讀取：backend/tests/unit/one-a-two-b.test.ts
```

## Bad Example

- 目標任務很小，卻讀取整個前後端尋找順手重構。

```markdown
目標任務：在 backend/src/game/one-a-two-b.ts 實作 scoreGuess
額外讀取：frontend/src/**、backend/src/ws/**、backend/src/db/**
```
