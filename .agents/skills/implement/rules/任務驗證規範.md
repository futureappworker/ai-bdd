# Rule 1 - 驗證必須對應這一個任務

- 驗證命令必須覆蓋本次目標任務直接修改或新增的行為。
- 必須優先使用與該任務最近的單一情境測試、整合測試、lint 或 typecheck。
- 無法執行自動驗證時，必須取得該任務的手動檢查證據。
- 不得只因為檔案已修改就判定任務通過。
- 不得用其他任務的驗證結果代替本次目標任務。

## Good Example

- 單一聊天情境任務只以該情境的執行結果作為驗證。

```text
Task: T005 bdd green
Validation: npx cucumber-js --name "^BE-1.1 玩家A、玩家B、房間 2468、送出成功$"
Result: PASS
```

## Bad Example

- 沒有自己的驗證，只借用另一次整體測試結果。

```text
Task: T005 bdd green
Validation: 先前整包 npm test
Result: PASS
```

# Rule 2 - 任務自身失敗必須先修正再進下一個任務

- 本次目標任務自身驗證失敗時，處置必須是修正目標任務。
- 修正範圍必須是該任務描述中的目標檔，或該任務 `References` 指向且本次任務需要的檔案。
- 修正後必須重新驗證同一個任務。
- 該任務自身驗證通過前，不得選擇下一個任務，也不得把 checkbox 改成 `[X]`。
- 任務標有 **BDD 子命令** 時，`implement` 必須依 `BDD子命令委派規範` 以獨立委派或等價子命令模式執行，並以該 BDD 流程的結果決定是否打勾或停止，不進入本規則的非 BDD 修正流程。
- 不得建立、讀取或寫入 `implement-run.md`。

## Good Example

- 同一個 `bdd green` 任務失敗後，先在同一情境與同一子命令內修正再重新驗證。

```text
Task: T005 bdd green
Result: FAIL expected latest message to equal "哈囉"
處置：把同一個子命令與位址再交給 bdd，或在等價子命令模式下修正同一情境
重新驗證：PASS
下一個任務：尚未選擇
```

## Bad Example

- `bdd green` 尚未通過，卻改去做下一個情境。

```text
Task: T005 bdd green
Result: FAIL expected latest message to equal "哈囉"
處置：選擇 T006
```

# Rule 3 - 範圍外失敗不得修改那些檔案

- 失敗不屬於本次目標任務的目標檔與 `References` 時，不得修改那些檔案。
- 本次目標任務自身驗證已通過時，處置必須是通過。
- 範圍外失敗不得使本次執行結束，也不得阻止選擇下一個任務。

## Good Example

- 聊天情境已通過，其他既有前端測試失敗不修改、也不中斷。

```text
Task: T005 bdd green
Result: PASS chat scenario
其他失敗：frontend/catalog.test.ts
處置：通過
```

## Bad Example

- 為了讓整個測試命令變綠，去修改不屬於本任務的檔案。

```text
Task: T005 bdd green
Result: PASS chat scenario
其他失敗：frontend/catalog.test.ts
處置：修正 frontend/catalog.test.ts
```

# Rule 4 - BDD 子命令的完成證據必須來自 BDD 流程

- 本次目標任務是 `BDD 子命令: red`、`green` 或 `refactor` 時，`implement` 不得把非 BDD 驗證流程的結果拿來取代該子命令的完成證據。
- 標有 **BDD 子命令** 的任務，其完成證據必須來自獨立 `/bdd` 回覆或等價子命令模式下的同一子命令結果。
- `red` 的有效失敗、`green` 的情境通過、`refactor` 的整理後仍通過，都必須由該 BDD 流程自己提供證據。

## Good Example

- 標有 **BDD 子命令** 的任務由 BDD 流程提供證據，而不是改用一般驗證規則。

```text
Task: T004 委派 /bdd red
處置：把場景、DSL 與目標檔交給 BDD 流程，等待完成證據
```

## Bad Example

- 標有 **BDD 子命令** 的任務仍由 `implement` 自行判定與修正。

```text
Task: T004 委派 /bdd red
處置：implement 直接修改 chat-service.ts
```

## Exceptions

- 任務標有 **BDD 子命令** 時，`implement` 不應進入本規則的非 BDD 驗證路徑；若仍進入，必須立即改依 `BDD子命令委派規範` 回到 BDD 流程。
- acceptance `.feature` 任務若標有 **BDD 子命令**，應由 BDD 流程提供 `red`、`green` 或 `refactor` 的完成證據；`implement` 不得自行把 acceptance 失敗改判為其他子命令結果。
