# Rule 1 - 驗證必須對應這一個任務

- 驗證命令必須覆蓋本次目標任務直接修改或新增的行為。
- 必須優先使用與該任務最近的單元測試、整合測試、lint 或 typecheck。
- 無法執行自動驗證時，必須取得該任務的手動檢查證據。
- 不得只因為檔案已修改就判定任務通過。
- 不得用其他任務的驗證結果代替本次目標任務。

## Good Example

- T019 只以它改到的計分測試作為驗證。

```text
Task: T019 implement scoreGuess
Validation: npm test -- one-a-two-b.test.ts
Result: PASS
```

## Bad Example

- T019 沒有自己的驗證，只借用另一次整體測試結果。

```text
Task: T019 implement scoreGuess
Validation: 先前 T018 的 npm test
Result: PASS
```

# Rule 2 - 任務自身失敗必須先修正再進下一個任務

- 本次目標任務自身驗證失敗時，處置必須是修正目標任務。
- 修正範圍必須是該任務描述中的目標檔，或該任務 References 指向且本次任務需要的檔案。
- 修正後必須重新驗證同一個任務。
- 該任務自身驗證通過前，不得選擇下一個任務，也不得把 checkbox 改成 `[X]`。
- 任務標有 TDD 步驟時，修正必須把同一個步驟、測試計劃案例與目標檔再交給 `tdd`。
- 不得建立、讀取或寫入 `implement-run.md`。

## Good Example

- scoreGuess 的斷言還沒通過，因此先修正該檔並重新驗證。

```text
Task: T019 implement scoreGuess
Result: FAIL expected aCount 4
處置：修正 backend/src/game/one-a-two-b.ts
重新驗證：PASS
下一個任務：尚未選擇
```

## Bad Example

- scoreGuess 尚未通過，卻改去做下一個任務。

```text
Task: T019 implement scoreGuess
Result: FAIL expected aCount 4
處置：選擇 T020
```

# Rule 3 - 範圍外失敗不得修改那些檔案

- 失敗不屬於本次目標任務的目標檔與 References 時，不得修改那些檔案。
- 本次目標任務自身驗證已通過時，處置必須是通過。
- 範圍外失敗不得使本次執行結束，也不得阻止選擇下一個任務。

## Good Example

- T019 的計分測試已通過，既有的前端測試失敗不修改、也不中斷。

```text
Task: T019 implement scoreGuess
Result: PASS one-a-two-b.test.ts
其他失敗：frontend/catalog.test.ts
處置：通過
```

## Bad Example

- 為了讓整個測試命令變綠，去修改不屬於 T019 的前端測試。

```text
Task: T019 implement scoreGuess
Result: PASS one-a-two-b.test.ts
其他失敗：frontend/catalog.test.ts
處置：修正 frontend/catalog.test.ts
```

# Rule 4 - 測試任務的預期失敗必須視為通過

- 本次目標任務是測試任務，且失敗原因對應尚未實作的目標行為時，處置必須是通過。
- 語法錯誤、錯誤 import、測試環境缺失，或測試無法執行到該失敗時，處置必須是修正目標任務。

## Good Example

- `scoreGuess` 尚未實作造成的失敗是預期紅燈，因此視為通過。

```text
Task: T017 撰寫 scoreGuess 測試
FAIL one-a-two-b.test.ts
Expected { aCount: 4, bCount: 0 }
Received { aCount: 0, bCount: 0 }
處置：通過
```

## Bad Example

- 同一個預期紅燈被當成要修正的實作失敗。

```text
Task: T017 撰寫 scoreGuess 測試
FAIL one-a-two-b.test.ts
Expected { aCount: 4, bCount: 0 }
Received { aCount: 0, bCount: 0 }
處置：修正 scoreGuess
```

## Exceptions

- 任務標有 TDD 步驟時，預期失敗的判定必須沿用 `tdd` 對該步驟的結果，不另寫一套失敗斷言。
- 總驗收任務的測試通過時，處置必須是通過。測試失敗時，處置必須是修正目標任務。不得把總驗收的失敗視為預期紅燈。
