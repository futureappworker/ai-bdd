# Rule 1 - Rule File 名稱與路徑

- Rule File 名稱必須描述指定步驟要加強把關的單一規則主題。
- Rule File 名稱必須以 `規範.md` 結尾。
- Rule File 必須放在目標 Skill 的 `rules/` 目錄。
- Rule File 路徑必須使用相對於目標 Skill `SKILL.md` 的 `rules/<檔名>` 形式。
- Rule File 名稱不得使用 `新規則`、`其他規則` 或 `補充規則` 等無法識別規則主題的名稱。
- Rule File 路徑不得覆寫與本次規則主題不同的既有檔案。

## Good Example

- 名稱指出 API 輸入驗證這個單一主題，路徑位於目標 Skill 的 `rules/` 目錄。

```text
rules/API輸入驗證規範.md
```

## Bad Example

- 名稱無法識別規則主題，且檔案沒有放在 `rules/` 目錄。

```text
補充規則.md
```

# Rule 2 - Rule File 載入位置

- Rule File 必須在指定步驟首次需要其內容時載入。
- Rule File 的 `Read` 步驟必須與指定步驟位於同一個 Phase。
- Rule File 的 `Read` 步驟必須緊鄰指定步驟之前。
- `Read` 步驟必須指出要從 Rule File 取得的要求。
- 不得為載入 Rule File 建立獨立 Phase。
- 不得在同一次 SOP 執行中重複載入相同 Rule File。

## Good Example

- Rule File 在指定步驟首次使用規範之前，於同一 Phase 載入。

```markdown
## Phase 2: 實作 API

1. Think 決定 endpoint 的輸入欄位。
2. Read [API 輸入驗證規範](rules/API輸入驗證規範.md)並取得驗證要求。
3. Write 依已載入規範建立 API endpoint。
```

## Bad Example

- Rule File 被提前放入獨立 Phase 載入，沒有在指定步驟首次需要時按需載入。

```markdown
## Phase 1: 載入規則

1. Read [API 輸入驗證規範](rules/API輸入驗證規範.md)並取得驗證要求。

## Phase 2: 實作 API

1. Think 決定 endpoint 的輸入欄位。
2. Write 依已載入規範建立 API endpoint。
```

# Rule 3 - 指定步驟使用衍生規則

- 指定步驟必須以「已載入規範」指稱衍生規則。
- 指定步驟必須保留原有的步驟動詞與行為目的。
- 加入 `Read` 步驟後，所屬 Phase 的步驟必須依執行順序重新連續編號。
- 未被指定的步驟必須保留原有內容與順序。
- 不得修改與本次規則整合無關的 Phase 或步驟。

## Good Example

- 指定步驟使用已載入規範，同時保留原有的 `Write` 動詞、建立 endpoint 的目的及其他步驟。

```markdown
## Phase 2: 實作 API

1. Think 決定 endpoint 的輸入欄位。
2. Read [API 輸入驗證規範](rules/API輸入驗證規範.md)並取得驗證要求。
3. Write 依已載入規範建立 API endpoint。
4. Write 撰寫對應測試。
```

## Bad Example

- 指定步驟沒有使用已載入規範，因此無法確認衍生規則會在執行時生效。

```markdown
## Phase 2: 實作 API

1. Think 決定 endpoint 的輸入欄位。
2. Read [API 輸入驗證規範](rules/API輸入驗證規範.md)並取得驗證要求。
3. Write 建立 API endpoint。
4. Write 撰寫對應測試。
```
