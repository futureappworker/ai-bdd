# Rule 1 - 掃描必須涵蓋固定十類

- 提問模式必須依下表十類掃描覆蓋，每一類都必須在內部標成清楚、部分或缺少。
- 不得省略任何一類。
- 分類只判斷現有規格是否已把該類事情說清楚。
- 不得為了補上缺少的類別而在 spec.md 新增章節。

| 分類 | 檢查點 |
|---|---|
| 功能範圍與行為 | 使用者目標、成功標準、明確不做的範圍、角色差異 |
| 領域與資料 | 實體、屬性、關係、身份與唯一性、生命週期、規模假設 |
| 互動流程 | 關鍵旅程、錯誤／空／載入狀態、無障礙或在地化 |
| 非功能品質 | 效能、擴展、可靠性、可觀測性、安全隱私、合規 |
| 外部整合 | 外部服務與失敗方式、匯入匯出格式、協定與版本假設 |
| 邊界與失敗 | 負面情境、速率限制、衝突處理 |
| 限制與取捨 | 已寫明的限制、已拒絕的替代方案 |
| 用語 | 正規名稱、應避免的同義詞 |
| 完成訊號 | 驗收能否測試、可量測的完成條件 |
| 未解占位 | TODO、無法量化的形容詞 |

## Good Example

- 十類都有內部狀態，規格沒有為了缺少的外部整合而新增章節。

```markdown
內部覆蓋：
- 功能範圍與行為 = 清楚
- 領域與資料 = 缺少
- 互動流程 = 部分
- 非功能品質 = 缺少
- 外部整合 = 缺少
- 邊界與失敗 = 清楚
- 限制與取捨 = 清楚
- 用語 = 清楚
- 完成訊號 = 部分
- 未解占位 = 清楚

spec.md 仍只有原本的章節。
```

## Bad Example

- 只標了少數幾類，並因為外部整合缺少而在規格裡新增章節。

```markdown
內部覆蓋：
- 領域與資料 = 缺少
- 用語 = 清楚

## 外部整合

- 尚未決定照片要不要上傳到外部服務。
```

# Rule 2 - 技術選型不得成為掃描檢查點

- 限制與取捨只檢查規格已寫明的限制，以及已拒絕的替代方案。
- 程式語言、儲存、託管與其他技術選型不得成為檢查點。
- 不得因為規格沒有選擇技術，就把限制與取捨標成部分或缺少。

## Good Example

- 規格已寫明相簿不嵌套，限制與取捨標成清楚；沒有資料庫選擇也不構成缺口。

```markdown
內部覆蓋：限制與取捨 = 清楚
依據：規格寫明相簿不得嵌套在其他相簿中。
```

## Bad Example

- 規格沒有選擇資料庫，就把限制與取捨標成缺少。

```markdown
內部覆蓋：限制與取捨 = 缺少
依據：規格尚未指定 PostgreSQL 或 SQLite。
```
