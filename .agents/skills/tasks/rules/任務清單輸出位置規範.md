# Rule 1 - 任務清單的輸出位置

- 任務清單必須寫入該功能 `plan.md` 所在目錄的 `tasks.md`。
- 不得把任務清單寫進 Skill 的 `templates/`。
- 不得另建與 `tasks.md` 並列的第二份任務清單。

## Good Example

- 任務清單寫在該功能 `plan.md` 所在目錄。

```text
specs/001-online-pvp-1a2b/plan.md
specs/001-online-pvp-1a2b/tasks.md
```

## Bad Example

- 同一份 `plan.md` 的任務清單被寫進 Skill 樣板。

```text
specs/001-online-pvp-1a2b/plan.md
.agents/skills/tasks/templates/tasks.md
```

# Rule 2 - 上游輸入

- 產生任務清單前必須讀取同一功能的 `testplan.md`、`plan.md` 與 `techstack.md`。
- `testplan.md` 不存在時，必須把缺少測試計劃寫入回覆並停止寫入 `tasks.md`。
- `plan.md` 不存在，或沒有原始碼落地位置，或沒有系統介面盤點時，必須把缺少的輸入寫入回覆並停止寫入 `tasks.md`。
- `techstack.md` 不存在，或沒有採用技術表時，必須把缺少的輸入寫入回覆並停止寫入 `tasks.md`。
- 上游輸入不足時，不得自行新增使用者故事、原子案例、原始碼目錄或技術選型。

## Good Example

- 測試計劃、系統分析與採用技術表都在，任務清單才寫入同一功能目錄。

```text
Input: specs/001-online-pvp-1a2b/testplan.md
Input: specs/001-online-pvp-1a2b/plan.md
Input: specs/001-online-pvp-1a2b/techstack.md
Output: specs/001-online-pvp-1a2b/tasks.md
```

## Bad Example

- 沒有採用技術表仍寫入任務清單，並自訂 Setup 要引用的技術。

```text
Missing: specs/001-online-pvp-1a2b/techstack.md
Output: specs/001-online-pvp-1a2b/tasks.md
```
