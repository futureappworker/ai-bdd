# Rule 1 - 任務清單的輸出位置

- 任務清單必須寫入該功能 `plan.md` 所在目錄的 `tasks.md`。
- 不得把任務清單寫進 Skill 的 `templates/`。
- 不得另建與 `tasks.md` 並列的第二份任務清單。

## Good Example

- 任務清單寫在該功能 `plan.md` 所在目錄。

```text
specs/002-player-chat/plan.md
specs/002-player-chat/tasks.md
```

## Bad Example

- 同一份 `plan.md` 的任務清單被寫進 Skill 樣板。

```text
specs/002-player-chat/plan.md
.agents/skills/tasks/templates/tasks.md
```

# Rule 2 - 上游輸入

- 產生任務清單前必須讀取同一功能的 `spec.md`、`plan.md`、`techstack.md`、`features/acceptance/` 與 `features/<interface>/` 下的 `.feature`、`dsl.md`。
- `spec.md` 不存在，或沒有使用者故事與全域需求時，必須把缺少的輸入寫入回覆並停止寫入 `tasks.md`。
- `plan.md` 不存在，或沒有原始碼落地位置，或沒有系統介面盤點時，必須把缺少的輸入寫入回覆並停止寫入 `tasks.md`。
- `techstack.md` 不存在，或沒有採用技術表時，必須把缺少的輸入寫入回覆並停止寫入 `tasks.md`。
- `features/acceptance/` 沒有驗收 feature，或 `features/<interface>/` 沒有介面 `.feature` 與 `dsl.md` 時，必須把缺少的輸入寫入回覆並停止寫入 `tasks.md`。
- 上游輸入不足時，不得自行新增使用者故事、介面情境、總驗收旅程、原始碼目錄或技術選型。

## Good Example

- 規格、系統分析與介面 Artifact 都在，任務清單才寫入同一功能目錄。

```text
Input: specs/002-player-chat/spec.md
Input: specs/002-player-chat/plan.md
Input: specs/002-player-chat/techstack.md
Input: specs/002-player-chat/features/acceptance/從房間聊到終局.feature
Input: specs/002-player-chat/features/backend/拒絕聊天送出.feature
Input: specs/002-player-chat/features/backend/dsl.md
Output: specs/002-player-chat/tasks.md
```

## Bad Example

- 沒有介面 `.feature` 與 `dsl.md` 仍寫入任務清單，並自行腦補介面情境。

```text
Missing: specs/002-player-chat/features/backend/
Output: specs/002-player-chat/tasks.md
```
