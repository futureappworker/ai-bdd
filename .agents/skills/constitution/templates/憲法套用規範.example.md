# 共同憲法

- 適用：寫入憲法產出的 Skill

# Rule 1 - I. 一份憲法檔只約束一份產出

- 憲法檔必須放在 `constitution/<skill>/<artifact>.md`。
- 檔頭必須標明 Skill 與產出路徑。
- 檔內每一條 Rule 必須只約束檔頭標明的那一份產出。
- 此規則確保路徑與檔頭能指出被約束的 Skill 產出。

## Good Example

- 檔頭指向一份產出，Rule 只約束這份產出的部位。

```markdown
# OpenAPI 憲法

- Skill: api-plan
- 產出: contracts/openapi.yaml

# Rule 1 - I. 成功回應信封

- 部位必須是 HTTP 成功回應所引用的 JSON schema。
```

## Bad Example

- 同一份憲法檔的檔頭指向 OpenAPI，Rule 卻改去約束 DBML。

```markdown
# OpenAPI 憲法

- Skill: api-plan
- 產出: contracts/openapi.yaml

# Rule 2 - II. 資料表保留期限

- 部位必須是 DBML 的每一張 Table。
- Table note 必須寫保留期限。
```

# Rule 2 - II. 點名部位以憲法為準

- 憲法 Rule 必須寫明部位。
- 被憲法 Rule 點名的部位必須以該 Rule 為準。
- 沒被任何憲法 Rule 點名的部位必須依 Skill 樣板。
- 此規則確保專案只改寫它點名的產出事項。

## Good Example

- 被點名的部位寫入憲法要求的內容，未被點名的部位保留樣板。

```markdown
未被點名的部位：依樣板保留。
被點名的部位：依憲法 Rule 寫入必備內容。
```

## Bad Example

- 憲法已點名該部位，寫出的內容在該部位仍只有樣板。

```markdown
未被點名的部位：依樣板保留。
被點名的部位：仍只寫樣板內容。
```

# Rule 3 - III. 憲法進入既有寫入與檢查

- 寫入該產出之前必須讀取對應憲法檔。
- 憲法檔不存在時必須只依 Skill 樣板寫入。
- 既有檢查必須逐條判定已載入的憲法 Rule。
- 既有修正必須把未通過的憲法 Rule 改到通過。
- 此規則確保憲法判定留在原 Skill 的寫入、檢查與修正。

## Good Example

- 撰寫前讀取該產出的憲法檔，並在原有檢查與修正中判定這些 Rule。

```markdown
## Phase 3: 撰寫產出

1. Read 讀取該產出的樣板。
2. Read 若存在，讀取 constitution/<skill>/<artifact>.md。
3. Write 寫入該產出。

## Phase 4: 檢查產出

1. Read 檢查樣板要求與已載入的憲法 Rule。

## Phase 5: 修正產出

1. Write 修正未通過的樣板要求與憲法 Rule。
```

## Bad Example

- 產出寫完後，另開一個憲法檢查階段才讀取憲法檔。

```markdown
## Phase 3: 撰寫產出

1. Write 只依樣板寫入該產出。

## Phase 6: 憲法檢查

1. Read 讀取 constitution/<skill>/<artifact>.md 並判定。
```

# Rule 4 - IV. 重疊或無法判定時停止

- 同一憲法檔不得有兩條 Rule 約束同一部位。
- 缺少部位的 Rule 不得套用。
- 要求新增流程階段或改寫 Skill 順序的 Rule 不得套用。
- 出現上述情況時必須在寫入前停止，並回報該 Rule。
- 此規則確保無法判定的憲法不會被部分套用。

## Good Example

- Rule 2 與 Rule 1 都約束部位甲，Skill 在寫入前停止並回報 Rule 2。

```markdown
# Rule 1 - I. 部位甲

- 部位必須是部位甲。
- 部位甲必須包含 `alpha`。

# Rule 2 - II. 部位甲的另一欄位

- 部位必須是部位甲。
- 部位甲必須包含 `beta`。
```

## Bad Example

- 兩個 Rule 約束同一部位時，Skill 只套用 Rule 1 並略過 Rule 2，仍然寫入該產出。

```markdown
套用 Rule 1。
略過與 Rule 1 部位相同的 Rule 2。
寫入該產出。
```
