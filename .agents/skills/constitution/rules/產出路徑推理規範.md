# Rule 1 - 產出路徑必須從目標 Skill 推理

- 憲法檔頭的產出路徑必須依目標 Skill 的寫入步驟、該步驟引用的產出樣板，以及專案中對該產出檔名的引用來決定。
- 使用者給出的純檔名不得作為產出路徑。
- Skill 目錄內的樣板路徑不得作為產出路徑。
- 憲法 Skill 自己的規則、樣板與已寫入的憲法檔不得作為推理來源。

## Good Example

- `api-plan` 的寫入步驟產出 OpenAPI，專案引用的路徑是 `contracts/openapi.yaml`，因此檔頭使用這條路徑。

```markdown
- 產出: `contracts/openapi.yaml`
```

## Bad Example

- 同一則 `api-plan` OpenAPI 憲法沿用使用者回答的檔名。

```markdown
- 產出: `openapi.yaml`
```

# Rule 2 - 採用穩定的專案相對路徑

- 目標 Skill 的規則已寫明輸出路徑時，必須採用該路徑。
- 目標 Skill 沒有寫明輸出路徑時，必須採用其他 Skill 引用該檔名時共同使用的專案相對路徑。
- 引用同時出現 feature 目錄前綴與不含該前綴的路徑時，必須採用不含 feature 目錄前綴的路徑。
- 候選路徑無法收成單一產出路徑時，產出路徑必須為空。

## Good Example

- 引用同時有 `specs/001-photo-album-organizer/contracts/openapi.yaml` 與 `contracts/openapi.yaml`，因此採用不含 feature 目錄前綴的路徑。

```text
contracts/openapi.yaml
```

## Bad Example

- 同一組引用改採某一個 feature 目錄下的路徑。

```text
specs/001-photo-album-organizer/contracts/openapi.yaml
```
