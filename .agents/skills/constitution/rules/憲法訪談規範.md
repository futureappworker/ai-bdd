# Rule 1 - 只問下一個會阻擋寫入的缺口

- 寫入目標是產出憲法且寫入動作是增量時，寫入一條憲法 Rule 之前，目標 Skill、產出路徑、部位，以及該部位的必備內容或禁止內容，必須都已決定。
- 目標 Skill 已決定時，不得再詢問 Skill。
- 產出路徑已決定時，不得再詢問產出。
- 部位已決定時，不得再詢問部位。
- 必備內容或禁止內容已決定時，不得再詢問該項。
- 寫入目標是產出憲法且目標 Skill 為空時，必須只提出 Skill 這一個問題。
- 目標 Skill 已決定且產出路徑為空時，必須只提出產出路徑這一個問題。
- 目標 Skill 與產出路徑都已決定且部位為空時，必須只提出部位這一個問題。
- 目標 Skill、產出路徑與部位都已決定，且必備內容與禁止內容都為空時，必須只提出必備內容或禁止內容這一個問題。
- 使用者只以檔名回答時，該回答不得視為目標 Skill 或產出路徑已決定。
- 上述條件都滿足時，不得再提出問題。
- 同一次提問不得同時詢問另一個尚未確認的項目。

## Good Example

- 查詢分頁描述已判斷出部位與必備內容，因此沒有問題。

```text
部位: 取得一頁資料的查詢操作
必備內容: 頁碼、每頁筆數、目前頁碼、本頁資料筆數、系統剩餘資料筆數
```

## Bad Example

- 同一則查詢分頁描述的部位與必備內容都已判斷，卻仍詢問部位。

```markdown
補部位：`contracts/openapi.yaml` 的哪一個部位要套用這條規範？
```

# Rule 2 - 問題只決定產出部位

- 問題必須指名它在補 Skill、產出路徑、部位、必備內容或禁止內容中的哪一項。
- 不得詢問流程順序、憲法版本或原始碼風格。
- 寫入目標是產出憲法，且使用者要求的是新活動而不是既有產出的部位時，必須改問要約束哪一份既有產出，或確認本次不寫入。

## Good Example

- 必備內容尚未判斷，問題只補必備內容。

```markdown
補必備內容：`contracts/openapi.yaml` 的查詢操作必須包含哪些內容？
```

## Bad Example

- 同一則必備內容尚未判斷，問題卻改問流程順序。

```markdown
要不要在 implement 之前新增一個測試階段？
```

# Rule 3 - 提問時不得寫入憲法

- 問題必須寫入回覆。
- 尚未決定的目標 Skill、產出路徑、部位、必備內容或禁止內容，不得寫入 `constitution/`。

## Good Example

- 必備內容尚未判斷，回覆只有這個問題，`constitution/` 沒有新增檔案。

```markdown
補必備內容：`contracts/openapi.yaml` 的查詢操作必須包含哪些內容？
```

## Bad Example

- 同一則必備內容尚未判斷，問題還在，卻先寫入憲法檔。

```markdown
補必備內容：`contracts/openapi.yaml` 的查詢操作必須包含哪些內容？
已寫入 constitution/api-plan/openapi.yaml.md
```

# Rule 4 - 必要憲法不沿用產出提問

- 寫入目標是必要憲法時，不得提出 Skill 或產出路徑問題。
- 寫入目標是必要憲法時，不得改問要約束哪一份既有產出。
- 寫入目標是必要憲法且寫入動作是增量時，產出路徑必須視為已決定。
- 寫入目標是必要憲法且寫入動作是增量，且部位為空時，必須只提出部位這一個問題。
- 寫入目標是必要憲法且寫入動作是增量，部位已決定，且必備內容與禁止內容都為空時，必須只提出必備內容或禁止內容這一個問題。

## Good Example

- 必要憲法檔已存在，部位尚未決定，因此只問要修改哪一條 Rule。

```markdown
補部位：`constitution/共同/憲法套用規範.md` 的哪一條 Rule 要修改？
```

## Bad Example

- 同一則必要憲法增量，部位尚未決定，問題卻改問 Skill。

```markdown
補 Skill：這條憲法要約束哪一個 Skill？
```
