# Rule 1 - 描述能收成一個部位時必須採用

- 使用者已點名部位時，必須採用該部位。
- 描述中的要求都能落在產出的同一個部位時，必須採用該部位。
- 查詢的請求參數與該查詢的成功回應屬於同一個查詢操作時，部位必須是該查詢操作。
- 成功回應 schema 與錯誤回應 schema 不得合成一個部位。
- 描述同時落在兩個無法合成的部位時，部位必須為空。
- 判斷出的部位與既有 Rule 的部位相同時，必須沿用該部位並交給後續寫入步驟處理重疊。

## Good Example

- 描述要求查詢請求帶頁碼與每頁筆數，成功回應帶回目前頁碼、本頁筆數與系統剩餘筆數，這些要求屬於同一個查詢操作。

```text
部位: 取得一頁資料的查詢操作
```

## Bad Example

- 同一則查詢分頁描述把部位留空。

```text
部位:
```

# Rule 2 - 必備或禁止內容只採用描述已寫明的項目

- 使用者已點名必備內容或禁止內容時，必須採用該內容。
- 必備內容必須來自描述裡已經寫明的項目。
- 禁止內容必須來自描述裡已經寫明的禁止項目。
- 描述沒有寫明的項目不得補成必備內容或禁止內容。

## Good Example

- 描述已寫明頁碼、每頁筆數、目前頁碼、本頁資料筆數與系統剩餘資料筆數，因此必備內容就是這些項目。

```text
必備內容: 頁碼、每頁筆數、目前頁碼、本頁資料筆數、系統剩餘資料筆數
```

## Bad Example

- 同一則描述的必備內容被留空。

```text
必備內容:
```

# Rule 3 - 描述不足時內容必須留空

- 描述沒有寫出具體必須項目時，必備內容必須為空。
- 描述沒有寫出具體禁止項目時，禁止內容必須為空。

## Good Example

- 描述只說「查詢 API 要規範一下」，沒有寫出頁碼或筆數，因此必備內容留空。

```text
必備內容:
```

## Bad Example

- 同一則描述沒有寫出欄位，卻補上頁碼與每頁筆數。

```text
必備內容: 頁碼、每頁筆數
```
