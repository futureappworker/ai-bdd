# Rule 1 - 驗收旅程必須寫入 acceptance 目錄

- 總驗收 feature 必須寫入目標 `spec.md` 所屬 Spec Package 的 `features/acceptance/`。
- 使用者明確指定 `spec.md` 路徑時，必須使用該 Spec Package。
- 使用者未指定路徑，且 `specs/` 下只有一個 Spec Package 時，必須使用該 package。
- 使用者未指定路徑，且存在多個 Spec Package、又無法從本次輸入判斷時，必須停下請使用者指定，不得自行挑選。
- `features/acceptance/` 不存在時，必須建立該目錄後再寫入 feature。

## Good Example

- 總驗收寫在該規格自己的 `features/acceptance/`。

```text
specs/001-online-1a2b-pvp/spec.md
specs/001-online-1a2b-pvp/features/acceptance/完成一局.feature
```

## Bad Example

- 總驗收寫進 Skill 的 templates 目錄，沒有落在 Spec Package。

```text
.agents/skills/spec-by-example/templates/完成一局.feature
```

# Rule 2 - 這一步只寫一份總驗收

- 這一步的 Gherkin 必須只放在 `features/acceptance/`。
- 這一步不得在 `features/acceptance/` 寫入 `dsl.md`。
- 這一步不得把同一批總驗收旅程寫入 `features/backend/` 或 `features/frontend/`。
- 這一步不得改寫 Spec Package 裡已存在的前後端 feature 或前後端 `dsl.md`。

## Good Example

- 目錄裡只有總驗收 feature，沒有把旅程再複製到前後端目錄。

```text
specs/001-online-1a2b-pvp/features/acceptance/完成一局.feature
specs/001-online-1a2b-pvp/features/acceptance/斷線重連.feature
```

## Bad Example

- 同一條總驗收被寫進後端目錄，並多寫了一份 `dsl.md`。

```text
specs/001-online-1a2b-pvp/features/acceptance/dsl.md
specs/001-online-1a2b-pvp/features/backend/完成一局.feature
```

# Rule 3 - 檔名必須點出旅程主題

- `zh-TW` feature 的檔名必須是繁體中文。
- 檔名必須點出該檔的 Demo 旅程主題。
- 一個 feature 檔必須只含一個 `功能`。
- 檔名不得使用 `feature`、`acceptance` 或 `test` 這類無法辨識旅程的名稱。

## Good Example

- 檔名能看出這是完成一筆訂單的旅程。

```text
features/acceptance/完成一筆訂單.feature
```

## Bad Example

- 檔名看不出旅程主題。

```text
features/acceptance/feature.feature
```
