# Rule 1 - 一個場景是一條 Demo 旅程

- 一個 feature 檔必須對應一條可 Demo 的旅程主題。
- 一條場景必須是從這條旅程的起點走到終點或走到分支停住的連續過程。
- 同一主題只留下主旅程，以及會改變結局的變種場景。
- 不得為了同一個終點的不同觀察欄位各寫一個場景。
- 不得為了單一運費城市、單一錯誤碼或單一欄位另開短場景。
- 變種場景必須從該旅程的起點寫到分支停住的那一步。

## Good Example

- 主旅程走完付清，變種停在結帳被拒，兩條都從選購寫起。

```gherkin
場景: SBE-1 會員A、SKU-1001 兩件、SAVE80、台北市、信用卡付清
  當 "會員A" 把商品 "SKU-1001" 加入購物車 1 件
  而且 "會員A" 套用優惠代碼 "SAVE80"
  而且 "會員A" 以配送地區 "台北市" 結帳
  而且 "會員A" 以 "信用卡" 支付 1800 元
  那麼 "會員A" 的訂單階段應該是 "已付款"

場景: SBE-3 會員A、SKU-1001 兩件、SAVE80、連江縣
  當 "會員A" 把商品 "SKU-1001" 加入購物車 1 件
  而且 "會員A" 套用優惠代碼 "SAVE80"
  而且 "會員A" 以配送地區 "連江縣" 結帳
  那麼 "會員A" 的訂單數量應該是 0
```

## Bad Example

- 同一筆付清被拆成加入購物車、套用優惠、結帳、付款四個短場景。

```gherkin
場景: SBE-1 加入購物車
  當 "會員A" 把商品 "SKU-1001" 加入購物車 2 件

場景: SBE-2 套用優惠
  當 "會員A" 套用優惠代碼 "SAVE80"
```

## Exceptions

- 當後一段旅程的 Demo 起點是前一段旅程已經成立的結果時，該結果必須寫成場景裡的 `假設`，不得把前一段旅程再走一遍。

# Rule 2 - 流程留在場景，沒有測試語意就不寫背景

- 總驗收的顆粒度是流程。一條場景就是一條流程，流程中的動作必須留在該場景裡。
- feature 預設不得寫 `背景`。
- 只有該檔每一個場景都共用、帶測試語意、而且終點斷言會用到的步驟，才可以抽成 `背景`。
- 清空資料、沒有進行中的單據、沒有進行中的房間、使用者已登入，不得寫成 `背景`。
- 旅程的起點與後續動作不得抽進 `背景`。
- 後段旅程承接前段結果時，必須使用場景裡的 `假設`，不得為了少寫流程而改成 `背景`。
- 當本規範與 gherkin-and-dsl 的背景寫法衝突時，必須採用本規範。gherkin-and-dsl 的背景規範只在已經決定寫 `背景` 時，約束 `背景` 裡可以放什麼。

## Good Example

- 商品目錄與折扣會被每一條結帳旅程的應付金額與可售數量用到，所以留在 `背景`。加入購物車仍是流程，留在場景。

```gherkin
背景:
  假設 商品目錄如下
    | 商品編號 | 賣家   | 單價 | 可售數量 |
    | SKU-1001 | 賣家甲 | 1000 | 10       |
  而且 賣家甲會員日為 9 折，優惠代碼 "SAVE80" 為折後滿 1000 折 80、每人一次

場景: SBE-1 會員A、SKU-1001 兩件、SAVE80、台北市、信用卡付清
  當 "會員A" 把商品 "SKU-1001" 加入購物車 1 件
  而且 "會員A" 把商品 "SKU-1001" 的數量改成 2
  而且 "會員A" 套用優惠代碼 "SAVE80"
  而且 "會員A" 以配送地區 "台北市" 結帳
  而且 "會員A" 以 "信用卡" 支付 1800 元
```

## Bad Example

- 同一條結帳旅程把「購物車是空的」和「已登入」抽成 `背景`。這兩句沒有被終點的應付金額或可售數量使用。

```gherkin
背景:
  假設 沒有進行中的購物車、訂單與付款
  而且 "會員A" 與 "會員B" 都已登入
  而且 商品目錄如下
    | 商品編號 | 賣家   | 單價 | 可售數量 |
    | SKU-1001 | 賣家甲 | 1000 | 10       |
  而且 賣家甲會員日為 9 折，優惠代碼 "SAVE80" 為折後滿 1000 折 80、每人一次

場景: SBE-1 會員A、SKU-1001 兩件、SAVE80、台北市、信用卡付清
  當 "會員A" 把商品 "SKU-1001" 加入購物車 1 件
  而且 "會員A" 把商品 "SKU-1001" 的數量改成 2
  而且 "會員A" 套用優惠代碼 "SAVE80"
  而且 "會員A" 以配送地區 "台北市" 結帳
  而且 "會員A" 以 "信用卡" 支付 1800 元
```

# Rule 3 - 旅程用一個當串起，驗收放在終點

- 一個場景必須正好有一個 `當`。
- 同一個 `當` 之後的後續動作必須使用 `而且`。
- `那麼` 必須寫在這條旅程最後一個動作之後。
- 不得在兩個動作之間插入 `那麼`。
- 會在中途停住的分支必須另開場景，不得在主旅程中途改寫結局。
- 一條 Rule 必須表達這條 Demo 的終點主張。
- 同一條旅程在終點要一起看到的事實必須留在同一個 Rule。
- 當本規範與 gherkin-and-dsl 的「一個觀察欄位一個場景」或「場景步驟維持在數句」衝突時，必須採用本規範的旅程顆粒度。

## Good Example

- 選購、結帳、付款串在同一個 `當` 後面，訂單事實留在終點。

```gherkin
當 "會員A" 把商品 "SKU-1001" 加入購物車 2 件
而且 "會員A" 以配送地區 "台北市" 結帳
而且 "會員A" 以 "信用卡" 支付 1800 元
那麼 "會員A" 的訂單應該符合
  | 訂單階段 | 應付金額 |
  | 已付款   | 1800     |
而且 商品 "SKU-1001" 的可售數量應該是 8
```

## Bad Example

- 結帳之後先寫 `那麼`，再寫第二個 `當` 付款。

```gherkin
當 "會員A" 以配送地區 "台北市" 結帳
那麼 訂單階段應該是 "待付款"
當 "會員A" 以 "信用卡" 支付 1800 元
那麼 訂單階段應該是 "已付款"
```

# Rule 4 - 形式必須能落地成 Gherkin

- feature 必須符合 gherkin-and-dsl 的階層與縮排、場景大綱、關鍵字、引號與同句步驟要求。
- 已寫入的 `背景` 必須符合 gherkin-and-dsl 的背景範圍。是否寫 `背景` 必須依本檔的流程規則決定。
- 第一行必須是 `# language: zh-TW`。
- 步驟關鍵字必須使用 `假設`、`當`、`那麼`、`而且`。
- `那麼` 必須使用「應該」寫出可觀察結果。
- 同一個動作出現在多個場景時，步驟文字必須相同。
- 場景標題必須寫出這組資料或這個分支，不得把 Rule 的主張再寫一次。
- 功能描述不得把尚未回答的缺口寫成已定規則。

## Good Example

- 標題寫的是哪一組資料，套用優惠這句在兩個場景用同一句文字。

```gherkin
場景: SBE-1 會員A、SKU-1001 兩件、SAVE80、台北市、信用卡付清
  而且 "會員A" 套用優惠代碼 "SAVE80"

場景: SBE-3 會員A、SKU-1001 兩件、SAVE80、連江縣
  而且 "會員A" 套用優惠代碼 "SAVE80"
```

## Bad Example

- 場景標題重述規則，而且同一個套用優惠動作被改寫成另一句。

```gherkin
場景: SBE-1 付清後必須留下已付款訂單
  而且 "會員A" 套用優惠代碼 "SAVE80"

場景: SBE-3 結帳條件不成立時必須拒絕結帳
  而且 "會員A" 輸入優惠代碼 "SAVE80"
```

# Rule 5 - 結果必須是系統可觀察事實

- 步驟必須寫角色、動作與業務結果。
- 金額、數量、階段、日期與拒絕原因必須寫在步驟或表格裡。
- 終點表格中的數字必須能從該場景的步驟與功能描述對上。
- 算法尚未回答時，必須保留一種暫定讀法，並在該步驟上方放置澄清標籤。
- 不得寫畫面元件、test id、URL、按鈕文字、HTTP 狀態碼或資料表欄位名稱。

## Good Example

- 終點寫訂單階段、應付金額與可售數量。

```gherkin
那麼 "會員A" 的訂單階段應該是 "已付款"
而且 "會員A" 的應付金額應該是 1800
而且 商品 "SKU-1001" 的可售數量應該是 8
```

## Bad Example

- 終點寫 HTTP 狀態碼與畫面 test id。

```gherkin
那麼 回應狀態碼應該是 201
而且 "會員A" 應該看見 test id "order-phase"
```
