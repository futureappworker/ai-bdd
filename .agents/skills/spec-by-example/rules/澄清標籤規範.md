# Rule 1 - 標籤必須貼在會被改寫的步驟正上方

- 會改寫某一個步驟、某一張表或某一條結局的缺口，必須在該步驟正上方用整行註解標出。
- 註解必須以 `# [Need Clarifications]` 開頭，後面寫問題、暫定讀法，以及其他場景的同一句是否一起等這個回答。
- 標籤不得寫進步驟句子。
- 同一題在整份總驗收裡必須只標一次。
- 功能描述不得把該缺口寫成已定規則。

## Good Example

- 標籤在支付步驟正上方，步驟本身仍是可讀的暫定金額。

```gherkin
# [Need Clarifications] 會員日 9 折與 SAVE80 誰先算？先打折再判斷滿額，應付是 1800；先扣 80 再打 9 折，應付是 1808。這一句先用 1800。SBE-4 的同一句也等這個回答。
而且 "會員A" 以 "信用卡" 支付 1800 元
```

## Bad Example

- 標籤寫進步驟句子，執行時會變成步驟的一部分。

```gherkin
而且 "會員A" 以 "信用卡" 支付 1800 元 [Need Clarifications]
```

# Rule 2 - 標籤數量必須落在三到十題

- 一份總驗收裡的 `[Need Clarifications]` 必須至少三個、最多十個。
- 少於三個時，必須再檢查會改變結局、金額、庫存時點、資格是否核銷或階段名稱的缺口，並補上會改寫步驟的標籤。
- 多於十個時，必須留下會改變 Demo 結局的十個，其餘維持暫定讀法且不另開標籤。
- 只影響單一城市運費、單一錯誤碼或單一欄位、又不會改寫既有旅程結局的事項，不得為了湊滿三題而標成澄清。

## Good Example

- 三題都落在會改寫既有步驟的位置：計價順序、庫存時點、折價券是否核銷。

```gherkin
# [Need Clarifications] 9 折與 SAVE80 誰先算？這一句先用 1800。
而且 "會員A" 以 "信用卡" 支付 1800 元
# [Need Clarifications] 加入購物車就預扣，還是結帳才預扣？本場景先照結帳才預扣。
當 "會員A" 把商品 "SKU-1001" 加入購物車 2 件
# [Need Clarifications] 結帳被拒後 SAVE80 是否算用過？這一句先寫尚未核銷。
而且 優惠代碼 "SAVE80" 對 "會員A" 應該尚未核銷
```

## Bad Example

- 為了湊數，把不會改寫旅程的按鈕顏色標成澄清。

```gherkin
# [Need Clarifications] 付款按鈕要用藍色還是綠色？
而且 "會員A" 以 "信用卡" 支付 1800 元
```

# Rule 3 - 寫完後必須依標籤順序澄清

- feature 寫入後，必須立刻依標籤澄清，不得只把標籤留在檔案裡。
- 提問順序必須依照 feature 檔名排序後、各檔由上到下的標籤出現順序。
- 單次必須交出尚未回答的標籤，且最多五題。
- 超過五題時，必須分成下一次繼續問完，不得丟棄尚未問到的標籤。
- 沒有未回答標籤時，不得再產生澄清問題。

## Good Example

- 檔內有七題時，這一次依出現順序問前五題，後兩題留到回答之後再問。

```text
本次鎖定題目：標籤 1、標籤 2、標籤 3、標籤 4、標籤 5
留下次：標籤 6、標籤 7
```

## Bad Example

- 檔內有七題，這一次只問影響較小的兩題，其餘標籤不再提問。

```text
本次鎖定題目：標籤 6、標籤 7
留下次：無
```

# Rule 4 - 已回答的標籤必須寫回步驟並移除

- 使用者已回答的標籤，必須把暫定讀法改成回答所決定的步驟、表格或結局。
- 同一題點名的其他場景必須一起改。
- 寫回後必須刪除該行 `# [Need Clarifications]` 註解。
- 已回答的缺口不得在後續撰寫時重新標成標籤。
- 回答若使某條變種場景的結局不再成立，必須改寫或移除該場景，不得保留與回答矛盾的步驟。

## Good Example

- 回答確定先打折再判斷滿額後，支付金額留下 1800，標籤刪除。

```gherkin
而且 "會員A" 以 "信用卡" 支付 1800 元
那麼 "會員A" 的應付金額應該是 1800
```

## Bad Example

- 已經回答先打折，步驟仍標著澄清，金額也改成另一種讀法。

```gherkin
# [Need Clarifications] 9 折與 SAVE80 誰先算？這一句先用 1800。
而且 "會員A" 以 "信用卡" 支付 1808 元
```
