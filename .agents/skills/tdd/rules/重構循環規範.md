# Rule 1 - 僅在綠燈後重構

- 重構必須在該案例的綠燈測試已經通過之後進行。
- 重構前與重構後都必須用專案既有的測試指令執行測試。
- 重構不得新增行為、分支、參數或公開介面。

## Good Example

- 本輪結帳測試已通過，重構前後都執行同一套測試指令。

```text
npm test
PASS user can checkout with valid cart
（重構：提取 priceCart）
npm test
PASS user can checkout with valid cart
```

## Bad Example

- 本輪測試尚未通過就提取模組，重構與綠燈階段混在一起。

```typescript
export async function checkout(cart, paymentMethod) {
  return confirmOrder(priceCart(cart), paymentMethod);
}
```

## Exceptions

- 當本輪接縫的受測部位是瀏覽器時，重構前後必須改以 Playwright 測試指令執行本輪測試。

# Rule 2 - 允許的重構

- 重構可以提取函式或模組、重新命名、搬移職責、消除重複或簡化條件。
- 重構後已確認接縫的公開介面與可觀察行為必須不變。

## Good Example

- 加總邏輯提取為 priceCart，checkout 的公開結果不變。

```typescript
function priceCart(cart) {
  return cart.lines.reduce((sum, line) => sum + line.price, 0);
}

export async function checkout(cart, paymentMethod) {
  const total = priceCart(cart);
  return chargeAndConfirm(total, paymentMethod);
}
```

## Bad Example

- 同一結帳流程在重構時新增空購物車拒絕，公開行為已改變。

```typescript
export async function checkout(cart, paymentMethod) {
  if (cart.lines.length === 0) {
    return { status: "rejected" };
  }
  return chargeAndConfirm(priceCart(cart), paymentMethod);
}
```

# Rule 3 - 禁止的重構

- 重構不得順便加入新功能或修正未測試的行為。
- 重構不得改變已確認接縫的語意。
- 重構不得為了通過測試而先改斷言或期望。
- 重構不得一次修改與本輪無關的多個模組。

## Good Example

- 重構只動本輪改過的 checkout 實作檔。

```text
修改範圍：src/checkout.ts
重構：提取 priceCart
```

## Bad Example

- 同一輪重構同時改 checkout、payment 與 cart 三個模組。

```text
修改範圍：src/checkout.ts、src/payment.ts、src/cart.ts
重構：整體分層
```

# Rule 4 - 小步與範圍

- 一次重構必須只做一類結構改善。
- 重構必須優先修改該案例綠燈觸及的實作檔。
- 重構執行結束前必須再執行一次專案既有的測試指令。

## Good Example

- 本輪只提取 priceCart，改完立刻跑測試。

```text
重構步驟：提取 priceCart
npm test
PASS
```

## Bad Example

- 同一輪重構同時提取 priceCart、重新命名 payment 模組並搬移 cart 型別。

```text
重構步驟：提取 priceCart、rename payment、move cart types
```

# Rule 5 - 重構與測試

- 重構不得新增測試。
- 重構後本輪測試與執行到的既有測試必須仍全部通過。
- 重構造成測試失敗時，必須先還原或縮小重構，或修正實作以恢復綠燈。
- 重構不得先改測試來配合新結構。

## Good Example

- 提取 priceCart 後測試仍全綠，測試檔未改。

```text
npm test
PASS user can checkout with valid cart
```

## Bad Example

- 提取 priceCart 後測試失敗，改為斷言內部函式 priceCart 被呼叫。

```typescript
test("checkout uses priceCart", async () => {
  await checkout(cart, paymentMethod);
  expect(priceCart).toHaveBeenCalled();
});
```

## Exceptions

- 當重構後公開行為不變而測試仍失敗，且該測試符合 [測試品質規範](rules/測試品質規範.md) Rule 2 的實作耦合定義時，可以在重構修正階段改寫該測試，並說明耦合原因。
