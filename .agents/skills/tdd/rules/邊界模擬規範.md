# Rule 1 - 只模擬系統邊界

- 跨越系統邊界的依賴必須在邊界處替換。
- 外部 API 必須以測試替身替換。
- 時間與隨機性必須由外部注入，並在測試中替換。
- 資料庫應該使用測試資料庫。無法提供測試資料庫時，可以改以測試替身替換，但必須在測試旁說明原因。
- 檔案系統應該使用臨時目錄或注入的邊界。無法使用真實臨時檔案系統時，可以改以測試替身替換，但必須在測試旁說明原因。

## Good Example

- 結帳測試替換外部付款客戶端，沒有呼叫真實付款 API。

```typescript
test("user can checkout with valid cart", async () => {
  const paymentClient = { charge: async () => ({ status: "confirmed" }) };
  const result = await checkout(cart, paymentClient);
  expect(result.status).toBe("confirmed");
});
```

## Bad Example

- 同一結帳測試直接建立真實付款客戶端，外部 API 沒有被替換。

```typescript
test("user can checkout with valid cart", async () => {
  const result = await checkout(cart, new StripeClient(process.env.STRIPE_KEY));
  expect(result.status).toBe("confirmed");
});
```

## Exceptions

- 當受測部位是瀏覽器時，不得把受測應用自己的瀏覽器、HTTP 與 WebSocket 換成測試替身。

# Rule 2 - 外部依賴由呼叫端注入

- 系統邊界上的依賴必須由呼叫端傳入。
- 被測行為不得在內部建立外部客戶端、讀取該客戶端的密鑰，或自行決定具體供應商。

## Good Example

- 付款客戶端由參數傳入，測試可以替換 charge。

```typescript
function processPayment(order, paymentClient) {
  return paymentClient.charge(order.total);
}
```

## Bad Example

- 同一付款行為在內部建立 Stripe 客戶端，測試無法只替換邊界。

```typescript
function processPayment(order) {
  const client = new StripeClient(process.env.STRIPE_KEY);
  return client.charge(order.total);
}
```

# Rule 3 - 邊界介面按操作拆開

- 每個外部操作必須是獨立函式。
- 測試替身的每個操作必須回傳一種固定結果。
- 邊界介面不得用單一通用請求函式包住全部操作。
- 測試替身不得依網址或參數分支決定回傳內容。

## Good Example

- 取得使用者與建立訂單分成兩個操作，替身各自回傳固定結果。

```typescript
const api = {
  getUser: async () => ({ id: "u1", name: "Alice" }),
  createOrder: async () => ({ id: "o1", status: "created" }),
};

const user = await api.getUser();
const order = await api.createOrder();
```

## Bad Example

- 同一組操作收成單一 fetch，替身必須依路徑分支才能回傳結果。

```typescript
const api = {
  fetch: async (endpoint: string) => {
    if (endpoint.startsWith("/users")) return { id: "u1", name: "Alice" };
    return { id: "o1", status: "created" };
  },
};
```
