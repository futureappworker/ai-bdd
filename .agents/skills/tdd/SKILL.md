---
name: tdd
description: Test-driven development. Use when the user wants to build features or fix bugs test-first, mentions "red-green-refactor", or wants integration tests. When a caller passes one step, run only that 紅燈, 綠燈, or 重構 step. When the subject under test is the browser, write and run that case with Playwright.
---

# SOP

## Phase 1: 決定本輪步驟

1. Read 讀取使用者輸入或呼叫方輸入，取得 TDD 步驟、測試計劃案例、目標測試檔與目標實作檔；未指定 TDD 步驟時，本輪步驟為完整循環。
2. Think 決定本輪步驟為紅燈、綠燈、重構或完整循環。

## Phase 2: 確認測試接縫

1. Read 讀取使用者需求或呼叫方給的測試計劃案例，以及即將修改的程式，取得要建立或修正的行為。
2. Read 讀取存在的 `GLOSSARY.md` 與修改範圍內的 ADR，取得領域詞彙與既有決策。
3. Read [測試接縫規範](rules/測試接縫規範.md)並取得接縫確認要求。
4. Read [瀏覽器端到端規範](rules/瀏覽器端到端規範.md)並取得瀏覽器受測部位的分類與 Playwright 要求。
5. Think 依已載入規範決定本輪接縫的受測部位是否為瀏覽器；是則將本輪接縫定為瀏覽器端到端。
6. Think 當本輪步驟是完整循環時，依已載入規範提出每條候選接縫的公開介面、抓到的行為與漏掉的行為，並在使用者確認前停止。
7. Think 當本輪步驟是紅燈、綠燈或重構時，依已載入規範把呼叫方給的測試計劃案例定為已確認接縫。
8. Think 當本輪步驟是綠燈時，決定進入 Phase 6，並停止本 Phase 之後的所有步驟。
9. Think 當本輪步驟是重構時，決定進入 Phase 9，並停止本 Phase 之後的所有步驟。

## Phase 3: 撰寫失敗測試

1. Read [測試品質規範](rules/測試品質規範.md)並取得公開行為、反模式、3A 註解分段與系統邊界的判斷要求。
2. Think 依已載入規範決定本輪要覆蓋的一條已確認接縫、該測試要觀察的公開行為，以及該接縫是否跨越系統邊界。
3. Read 本輪接縫跨越系統邊界時，讀取 [邊界模擬規範](rules/邊界模擬規範.md)並取得邊界依賴的模擬要求。
4. Think 依已載入規範決定本輪測試要替換的外部依賴。
5. Read [紅燈綠燈循環規範](rules/紅燈綠燈循環規範.md)並取得單輪失敗測試的範圍要求。
6. Write 依已載入規範將本輪這一條測試寫入本輪接縫對應的測試檔。

## Phase 4: 檢查失敗測試

1. Read 依已載入規範檢查本輪測試檔與本輪測試的執行輸出，並列出不符合項目。

## Phase 5: 修正失敗測試

1. Write 依已載入規範修正本輪測試檔的全部不符合項目。
2. Think 當本輪步驟是紅燈時，決定結束本次 tdd 執行，並停止本次 SOP 的所有後續步驟。

## Phase 6: 實作最小通過

1. Read 若尚未載入 [紅燈綠燈循環規範](rules/紅燈綠燈循環規範.md)，讀取該規範並取得單輪失敗測試與最小實作要求。
2. Delegate 當本輪步驟是綠燈時，依已載入規範使用專案既有測試指令取得本輪測試的失敗輸出。
3. Think 當本輪步驟是綠燈時，依已載入規範決定該失敗輸出是否允許進入最小實作；不允許時，決定結束本次 tdd 執行，並停止本次 SOP 的所有後續步驟。
4. Write 依已載入規範修改本輪接縫的實作檔，使本輪測試通過。

## Phase 7: 檢查實作

1. Read 依已載入規範檢查本輪實作檔與本輪測試的執行輸出，並列出不符合項目。

## Phase 8: 修正實作

1. Write 依已載入規範修正檢查所列不符合項目所在的本輪實作檔或本輪測試檔。
2. Think 當本輪步驟是綠燈時，決定結束本次 tdd 執行，並停止本次 SOP 的所有後續步驟。

## Phase 9: 決定是否重構本輪

1. Read [重構循環規範](rules/重構循環規範.md)並取得重構範圍與禁止事項。
2. Think 依已載入規範列出本輪可做的結構改善，或得出本輪跳過重構；若跳過重構，決定進入 Phase 13，並停止本 Phase 之後的所有步驟。

## Phase 10: 執行重構

1. Write 依已載入規範修改該案例綠燈觸及的實作檔。

## Phase 11: 檢查重構

1. Read 依已載入規範執行專案測試指令，檢查本輪相關測試與既有測試的執行輸出，並列出不符合項目。

## Phase 12: 修正重構

1. Write 依已載入規範修正檢查所列不符合項目所在的本輪實作檔或本輪測試檔。

## Phase 13: 決定下一輪

1. Think 當本輪步驟是紅燈、綠燈或重構時，決定本次不再進入下一輪。
2. Think 當本輪步驟是完整循環時，判斷已確認接縫是否都已有對應測試；若仍有未覆蓋接縫，從 Phase 3 再執行一輪。
