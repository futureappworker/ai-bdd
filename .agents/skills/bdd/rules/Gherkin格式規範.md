# Rule 1 - 語言與關鍵字

- 每個 feature 檔第一行必須是 `# language: <語言碼>`。
- 專案已有 feature 時，新 feature 的語言碼必須與既有 feature 相同。
- 專案沒有 feature 時，語言碼必須是 `zh-TW`。
- 標題關鍵字必須使用該語言的官方拼法，而且冒號緊接在關鍵字後面。
- `zh-TW` 的標題關鍵字必須使用 `功能`、`Rule`、`背景`、`場景` 或 `劇本`、`場景大綱` 或 `劇本大綱`、`例子`。
- `zh-TW` 的步驟關鍵字必須使用 `假設`、`假如`、`假定`、`當`、`那麼`、`而且`、`並且`、`同時`、`但是`。
- 同一個 feature 檔應該固定一組步驟關鍵字：`假設`、`當`、`那麼`、`而且`、`但是`。
- 步驟關鍵字後面不得加冒號。
- 英文步驟關鍵字含尾端空白；`Given:` 這種寫法不會成為步驟。中文步驟關鍵字不含尾端空白；`假設:` 會變成文字以冒號開頭的另一句步驟。

## Good Example

- 第一行宣告 `zh-TW`，標題有緊接冒號，步驟沒有冒號。

```gherkin
# language: zh-TW
功能: 從帳戶提款

  場景: 餘額不足
    假設 帳戶 "A-1" 的餘額是 20
    當 客戶從帳戶 "A-1" 提取 40
    那麼 提領應該被拒絕，原因是 "餘額不足"
```

## Bad Example

- 步驟關鍵字後面加了冒號，這句不會依原意執行。

```gherkin
# language: zh-TW
功能: 從帳戶提款

  場景: 餘額不足
    假設: 帳戶 "A-1" 的餘額是 20
    當 客戶從帳戶 "A-1" 提取 40
    那麼 提領應該被拒絕，原因是 "餘額不足"
```

# Rule 2 - 一個檔案一個功能

- 一個 `.feature` 必須剛好有一個功能標題。
- 縮排應該使用 2 個空白。
- 註解必須是整行 `#`。
- `功能`、`場景`、`背景`、`場景大綱`、`Rule` 底下的自由描述不得以關鍵字開頭。
- 自由描述不會被執行；要檢查的條件必須寫成步驟或 `例子` 儲存格。

## Good Example

- 檔案只有一個 `功能`，描述沒有以關鍵字開頭。

```gherkin
# language: zh-TW
功能: 從帳戶提款

  已登入的客戶可以從自己的帳戶提取現金。

  場景: 餘額不足
    假設 帳戶 "A-1" 的餘額是 20
    當 客戶從帳戶 "A-1" 提取 40
    那麼 提領應該被拒絕，原因是 "餘額不足"
```

## Bad Example

- 描述行以步驟關鍵字開頭，執行時會變成額外步驟。

```gherkin
# language: zh-TW
功能: 從帳戶提款

  假設 客戶已經登入

  場景: 餘額不足
    假設 帳戶 "A-1" 的餘額是 20
    當 客戶從帳戶 "A-1" 提取 40
    那麼 提領應該被拒絕，原因是 "餘額不足"
```

# Rule 3 - 步驟文字全域唯一

- 同一次執行會載入的全部 feature 中，去掉關鍵字後的步驟文字必須唯一。
- 比對前必須把連續空白收成一個空白。
- `假設` 與 `那麼` 的文字相同時必須改寫結果句，結果句應該使用「應該」。
- 檢查 Script 回報 `duplicate-step-text` 時，必須修改本次 feature 的句子以消除重複。
- 不得為了消除重複去改寫本次範圍以外的既有 feature。

## Good Example

- 前置與結果使用不同文字，結果句帶有「應該」。

```gherkin
假設 帳戶 "A-1" 的餘額是 20
那麼 帳戶 "A-1" 的餘額應該是 20
```

## Bad Example

- 關鍵字不同但文字相同，執行時會被視為重複步驟。

```gherkin
假設 帳戶 "A-1" 的餘額是 20
那麼 帳戶 "A-1" 的餘額是 20
```

# Rule 4 - 檢查報告的 error 必須修正

- `check-gherkin.py` 報告中 severity 為 `error` 的每個 finding 都必須修正。
- severity 為 `skipped` 的 `unsupported-language` 不得用更換關鍵字來消除。
- 出現 `unsupported-language` 時，必須改依該語言的官方 Gherkin 關鍵字完成同等檢查，並把違規列入不符合項目。
- 修正必須改 feature 文字，不得關閉或略過檢查 Script。

## Good Example

- 報告指出重複步驟後，改寫本次 feature 的結果句再交付 Review。

```text
code: duplicate-step-text
修正：把「那麼 帳戶 "A-1" 的餘額是 20」改成「那麼 帳戶 "A-1" 的餘額應該是 20」。
```

## Bad Example

- 報告已指出重複步驟，仍以原句交付 Review。

```text
code: duplicate-step-text
處理：這只是警告，feature 先不改。
```

## Exceptions

- 當 finding 的 severity 是 `skipped` 且 code 是 `unsupported-language` 時，可以不改 feature 文字，但必須完成該語言的人工同等檢查。
